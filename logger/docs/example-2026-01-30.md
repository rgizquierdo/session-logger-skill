### Key Learnings
- **Status Line Architecture**: Not a slash command — it's configured via `settings.json` with a `"type": "command"` that pipes JSON data to a script. The script parses and formats the output.

- **ccusage Tool**: Third-party utility that handles status line complexity. Install with `npx -y ccusage@latest statusline`. No need to manually install `jq` or write parsing scripts.

- **Skills vs Slash Commands**: Skills (in `.claude/skills/`) are more powerful — they support multiple files, templates, and can be auto-invoked by context. Slash commands are simpler single-file prompts.

### Key Learnings
- **Skill Structure**: A skill is a folder with a `SKILL.md` file. The SKILL.md contains instructions for Claude on how to perform the task. Can include YAML frontmatter with `name` and `description`.

- **Session State Pattern**: Using a JSON file (`.session-state.json`) to track session data allows persistence between Claude interactions. Critical for workflows that span multiple prompts.

- **Git Integration in Skills**: Skills can include bash commands for git operations. The pattern is: stage → commit with meaningful message → push. Always check if remote exists before pushing.
