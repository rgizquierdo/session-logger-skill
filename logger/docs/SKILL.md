# Session Logger Skill

You help Rolando track his Claude Code learning journey with structured daily logs, automatic summaries, and git integration.

## Commands

| Command | Action |
|---------|--------|
| `session start` | Begin a new session with goals |
| `session end` | Summarize, create log, commit to git |
| `session status` | Check if session is active |
| `session log [note]` | Add a quick note to current session |

---

## SESSION START Workflow

When user says "session start" or similar:

### Step 1: Check for existing session
```bash
cat .session-state.json 2>/dev/null && echo "EXISTS" || echo "NONE"
```

If session exists, ask: "You have an active session. End it first, or discard and start fresh?"

### Step 2: Gather session info (conversational, not interrogative)

Ask naturally:
- "What's your focus for this session?" (e.g., learning skills, building feature, studying AWS)
- "Any specific goals you want to accomplish?"

### Step 3: Create session state file

```bash
# Ensure logs directory exists
mkdir -p .logs/$(date +%Y/%m)
```

Create `.session-state.json`:
```json
{
  "id": "session-YYYYMMDD-HHMMSS",
  "started_at": "2026-01-30T14:30:00-05:00",
  "focus": "User's stated focus",
  "goals": ["Goal 1", "Goal 2"],
  "notes": [],
  "status": "active"
}
```

### Step 4: Display confirmation

```
╔══════════════════════════════════════════════════════════════╗
║  🚀 SESSION STARTED                                          ║
╠══════════════════════════════════════════════════════════════╣
║  📅 Date: January 30, 2026                                   ║
║  🕐 Started: 2:30 PM EST                                     ║
║  🎯 Focus: [their focus]                                     ║
║  📝 Goals:                                                   ║
║     • [Goal 1]                                               ║
║     • [Goal 2]                                               ║
╚══════════════════════════════════════════════════════════════╝

💡 Tips:
   • Say "session log [note]" to capture important moments
   • Say "session end" when you're done
   
Let's get started! What would you like to work on first?
```

## SESSION END Workflow

When user says "session end" or similar:

### Step 1: Verify active session
```bash
cat .session-state.json 2>/dev/null || echo "NO_SESSION"
```

If no session, offer to create a retroactive log.

### Step 2: Calculate duration
From `started_at` in session state to current time.

### Step 3: Gather session data

**A. Get git changes:**
```bash
git diff --name-status HEAD~10 2>/dev/null | head -20
git log --oneline -10 --since="$(cat .session-state.json | grep started_at | cut -d'"' -f4)" 2>/dev/null
```

**B. Get recently modified files:**
```bash
find . -type f -mmin -180 \
  -not -path './.git/*' \
  -not -path './node_modules/*' \
  -not -path './.logs/*' \
  -not -name '.session-state.json' \
  2>/dev/null | head -15
```

**C. Review conversation history:**
Analyze this conversation for:
- Tasks completed
- Commands/skills learned
- Challenges faced
- Key insights

### Step 4: Quick reflection (keep it fast)

Ask briefly:
- "What was your biggest win this session?"
- "Anything you want to remember for next time?"

### Step 5: Generate the log file

Create `.logs/YYYY/MM/YYYY-MM-DD.md` using the template below.

**If file exists** (multiple sessions same day): Append a new session section.

### Step 6: Update INDEX.md

Add entry to `.logs/INDEX.md`:
```markdown
- [2026-01-30](2026/01/2026-01-30.md) - [Focus area] - [Duration]
```

### Step 7: Git operations

```bash
# Stage logs
git add .logs/

# Commit with structured message
git commit -m "📝 Log: $(date +%Y-%m-%d) - [Focus area]

Session: [Duration]
Key accomplishments:
- [Accomplishment 1]
- [Accomplishment 2]

[auto-generated by session-logger]"

# Push if remote exists
git push origin $(git branch --show-current) 2>/dev/null || echo "No remote or push failed"
```

### Step 8: Clean up session state
```bash
rm .session-state.json
```

### Step 9: Display summary

```
╔══════════════════════════════════════════════════════════════╗
║  ✅ SESSION COMPLETE                                         ║
╠══════════════════════════════════════════════════════════════╣
║  ⏱️  Duration: 2 hours 15 minutes                            ║
║  📊 Focus: Learning Claude Code Skills                       ║
║  📁 Log: .logs/2026/01/2026-01-30.md                        ║
║  📤 Git: Committed & Pushed                                  ║
╚══════════════════════════════════════════════════════════════╝

🏆 Session Highlights:
   • [Key accomplishment 1]
   • [Key accomplishment 2]

📌 For Next Time:
   • [Suggested next step]

Great work today, Rolando! 💪
```

## SESSION LOG (Quick Note) Workflow

When user says "session log [something]":

1. Read `.session-state.json`
2. Append to the `notes` array:
   ```json
   {
     "timestamp": "ISO-8601",
     "note": "What they said"
   }
   ```
3. Brief confirmation: `📝 Noted: "[truncated note...]"`

---

## IMPORTANT GUIDELINES

1. **Be encouraging** — Celebrate progress, learning is hard work
2. **Be specific** — Generic logs aren't useful; capture concrete details
3. **Be quick** — The end-of-session process should take 2-3 minutes max
4. **Capture commands** — This is a Claude Code learning project; commands are gold
5. **Include context** — Why something was done matters as much as what
6. **Respect flow** — If user seems rushed, offer a "quick mode"

## QUICK MODE

If user says "session end quick":
- Skip reflection questions
- Auto-generate summary from conversation
- Minimal output
- Still commit to git

---

## RETROACTIVE LOGGING

If user wants to log a session after the fact (no active session):

1. Ask what they worked on and for how long
2. Ask for 2-3 key accomplishments
3. Generate a condensed log
4. Commit to git
